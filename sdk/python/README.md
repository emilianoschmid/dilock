# Dilock — Python

Status: draft-1 Redis and etcd SDKs with opt-in local integration tests. The etcd adapter targets the official v3.7.2 gRPC wire API using the upstream-derived, license-preserved protocol subset under `src/dilock/_etcd_proto/`. Redis strict mutual exclusion assumes one writable authority that preserves lock state; asynchronous replica promotion can lose a held key and is unsupported for this guarantee. This does not establish quorum, failover, restore safety, or protected-resource fencing.

Design: asyncio; structural Protocol; async context manager; dataclasses for options; native exceptions; py.typed.

Install from this checkout with `python -m pip install '.[redis]'` or `python -m pip install '.[etcd]'`. Use `RedisProvider(url, epoch="...")` or `EtcdProvider(endpoint, epoch="...")` for the default namespace and default acquisition policy; pass `namespace` and immutable `default_acquisition=AcquireOptions(...)` to configure them. Each handle's `hold()` async context manager acquires and releases using that same provider; explicit `async with await handle.acquire(...)` and `lease.release()` remain supported. Handles and leases are bound to their creating asyncio loop. `try_acquire` returns `None` only for acknowledged contention. After Redis reports contention, the SDK makes one bounded, read-only `TYPE` request: strings and expired keys remain busy, other key types raise `ProtocolMismatch`, and a failed classification raises `BackendUnavailable`. After a dispatched Redis `SET`, a lost reply or timeout raises `AcquisitionUnknown` even if owner-checked cleanup is acknowledged, because the original `SET` could still execute later. Cancellation remains `CancelledError` only when owner cleanup is acknowledged; otherwise the SDK raises `AcquisitionUnknown`. Backend errors remain distinct from contention. Every etcd acquisition receives a fresh server lease and owns its native Lock key. Release spends one independent cleanup budget across Unlock and LeaseRevoke together; the second RPC receives only the monotonic time remaining after the first. Process exit relies on server TTL. `lease.lost` is local notice and does not cancel arbitrary work. Redis auto-renewal is opt-in; etcd keepalive runs while the native Lock RPC waits. etcd exposes an epoch-scoped `create_revision` fence; the protected resource must atomically enforce it. A successful scope exit requires release outcome `RELEASED`; `ALREADY_NOT_OWNED` and `UNKNOWN` raise `ScopeReleaseError` with the exact outcome. If the body raises, its exception stays primary and cleanup diagnostics are reported through the optional callback (or Python logging). Neither adapter claims exactly-once effects or that lease expiry stops old processes.

For etcd release, `RELEASED` requires exact-key ownership evidence and acknowledged native `Unlock` and `LeaseRevoke`. A confirmed missing/mismatched key, absent lease, or acknowledged unique-lease revoke after confirmed ownership returns `ALREADY_NOT_OWNED` when those full release acknowledgements are unavailable. Uncertain ownership or cleanup returns `UNKNOWN`; an `Unlock` acknowledgement alone is insufficient. Repeated calls return the cached outcome and do not replay either operation. Cleanup after an acquisition failure uses one monotonic budget: stopping the waiter keepalive consumes part of that budget, and LeaseRevoke receives only the remainder. If no time remains or revoke is unacknowledged, acquisition cleanup raises `AcquisitionUnknown`; the attempt lease then expires under the configured etcd TTL. Ownership verification and keepalive shutdown are included in the overall acquisition wait; a late positive acquisition returns `WaitTimeout` only after confirmed abandonment, otherwise `AcquisitionUnknown`.

Before use, an administrator must explicitly provision matching draft-1 metadata; ordinary clients never create or repair it. For Redis, use `python tools/provision.py --endpoint redis://127.0.0.1:6379 --namespace app --epoch deployment-2026-01`. For etcd, create `/dilock/namespaces/<namespace>/meta` with the profile `etcd-native-lock-v1` and the approved epoch before connecting. See [Redis quickstart](../../docs/examples/python-redis/quickstart/README.md) and [etcd quickstart](../../docs/examples/python-etcd/quickstart/README.md) for minimal and configured examples. Review `../../spec/backends/REDIS.md` and `../../spec/backends/ETCD.md` for profile limits. The tested etcd process is a single-member functional server and says nothing about quorum, failover, or restore safety. Distribution: local project package only; nothing has been published.

Build/test: `python -m pytest`, `python -m mypy src/dilock`, `python -m ruff check src tests`, and `python -m build`. Real Redis tests require `DILOCK_REDIS_URL`; etcd tests require `DILOCK_ETCD_ENDPOINT`, `DILOCK_ETCD_NAMESPACE`, and `DILOCK_ETCD_EPOCH`. Skipped integration tests are not evidence. Client versions are pinned in their optional extras.

Use `../../spec/` for semantics and `../../docs/api/LANGUAGE-DESIGN.md` for design. Do not publish before real backend, conformance and installed-package tests pass.
