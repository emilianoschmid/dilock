# C++ package consumer

Run the exact-artifact consumer on Linux from the repository root. It builds
and consumes the Redis, etcd and PostgreSQL CMake targets:

```sh
python3 sdk/cpp/consumers/package_consumer.py \
  --toolchain-file .tools/cpp-conan-etcd/generators/conan_toolchain.cmake \
  --output validation/implementation/cpp-package-consumer.json \
  --scratch .tools/cpp-package-consumer
```

Generate that toolchain for the optional etcd profile with Conan's
`with_etcd=True` option. The recipe keeps Protobuf and gRPC out of its default
Redis-only profile. The consumer passes the same toolchain to both CMake
configure phases so the installed package's `find_dependency` calls can
resolve the etcd dependencies.

```sh
conan install sdk/cpp --output-folder .tools/cpp-conan-etcd -o "&:with_etcd=True"
```

The scratch directory must be new or empty. CMake configures the current SDK
with Redis, etcd and PostgreSQL enabled, installs and archives that build, extracts
the archive, then builds and runs this external consumer against the extracted
prefix. The consumer performs a default-policy acquire and acknowledged release
against both backends. Set `DILOCK_REDIS_HOST`, `DILOCK_ETCD_ENDPOINT`,
`DILOCK_NAMESPACE`, and `DILOCK_EPOCH` to disposable authorities with
pre-provisioned matching metadata before running it. Defaults target loopback,
namespace `consumer`, and epoch `local-consumer`; the SDK never provisions or
repairs metadata. This check does not contact a package registry. All native
dependencies must already be available through the toolchain's normal CMake
package search paths; the driver never downloads them. This archive profile is
Linux-only.

For the current-source Docker consumer and the public minimum/configured/shared
provider quickstarts, use `run_exact_package_quickstarts.sh` inside the pinned
local builder image. It creates a fresh dual-backend install, archives and
extracts that exact package, then configures and runs the external consumer and
all six Redis/etcd quickstart modes. The two development namespaces must be
provisioned explicitly before that run. The command writes its report to the
local validation directory; review the report generated by your own run.
