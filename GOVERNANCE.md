# Governance

Initial model: maintainer-led project with public technical decisions. The actual maintainer GitHub identities remain to be configured by the owner. No foundation, company sponsorship or multi-person steering committee is claimed.

Use ADRs for protocol, backend guarantees, public API and repository/release policy changes. A safety regression blocks promotion regardless of feature demand. Adding a language/backend requires a maintainer, native API review, conformance coverage, packaging tests and ongoing CI cost consideration.

The owner approves remote publication, licensing identity and repository access. Contributors do not need a mandatory CLA/DCO under this blueprint; any future policy change must be explicit. Publish maintenance scope and supported versions as evidence becomes available.
